# 유저 행동 분석 (dbt + BigQuery)

> 작성 중. 아래는 분석 전에 정한 지표 정의이며, 아직 SQL로 구현하거나 실행하지 않았다.

## 지표 정의

| 항목 | 정의 | 이렇게 정한 이유 |
|---|---|---|
| 데이터 | GA4 공개 샘플 `bigquery-public-data.ga4_obfuscated_sample_ecommerce`, 2020-11-01 ~ 2021-01-31 | 공개 샘플이 제공하는 기간 전체를 그대로 사용한다. |
| 사용자 단위 | `user_pseudo_id` (기기/브라우저 기준 익명 ID) | 로그인 ID 없이 모든 이벤트에 붙는 식별자다. 한 사람이 여러 기기를 쓰면 여러 명으로 집계되는 한계가 있다. |
| DAU | 그날 참여 세션(`session_engaged = 1`)이 1개 이상인 사용자 수 | 들어왔다 바로 나간 방문을 활성 사용자에서 빼기 위해서다. |
| WAU / MAU | 주·월 단위로 참여 세션이 있는 사용자를 다시 중복 제거해 센 수 (DAU를 더하지 않음) | 여러 날 방문한 사용자가 DAU 합계에서는 중복으로 세어지기 때문이다. |
| 월간 구매 고객 수 | 그 달에 `purchase` 이벤트가 1회 이상인 사용자 수 | 구매 건수가 아니라 구매한 사람 수를 보기 위해서다. 한 달에 여러 번 산 사용자도 1명으로 센다. |
| 퍼널 | 사람 기준, 단계 순서 무관(open). 단계: `view_item` → `add_to_cart` → `begin_checkout` → `purchase` | 이벤트 순서가 뒤바뀌거나 중간 이벤트가 빠진 구매자를 엄격한 순서 조건이 퍼널에서 떨어뜨리지 않게 하려는 것이다. |
| 퍼널 보조 지표 | 구매자 중 `add_to_cart` 없이 구매한 사용자 비중 | open 퍼널은 단계를 건너뛴 경우를 드러내지 않으므로 그 규모를 따로 확인한다. |
| 리텐션 코호트 | 주 단위 코호트, 주 시작은 일요일(BigQuery `WEEK` 기본값) | 미국 시간 기준 데이터이고, 미국 기업에서는 주로 일~토를 한 주로 보기 때문이다. |
| 코호트 진입 | 첫 방문 주. `user_first_touch_timestamp`가 2020-11-01 이후인 사용자만 포함 | 데이터 시작 전에 처음 방문한 사용자가 11월 첫 주 신규 사용자로 잘못 들어가지 않게 하기 위해서다. |
| n주차 리텐션 | 코호트 사용자 중 n주차에 다시 방문한 사용자 비율. 재방문은 ① 아무 이벤트 ② 참여 세션, 두 기준으로 따로 계산 | 아무 이벤트 기준에는 바로 이탈한 재방문도 포함된다. 두 기준을 함께 보면 단순 재방문과 실제 참여의 차이를 알 수 있다. |
| 리텐션 제외 구간 | 7일이 안 되는 마지막 주(2021-01-31 시작 주) 제외 | 2021-01-31은 일요일이라 그 주에는 하루치 데이터만 있다. 포함하면 리텐션이 낮게 나온다. |

## 다음에 볼 것 (예정)

지표를 구현한 뒤 아래 질문을 볼 예정이다.

- **첫 방문 → 첫 참여 리드타임**: 처음 방문한 뒤 첫 참여 세션까지 걸리는 시간
- **첫 참여 세션의 첫 이벤트**: 처음 참여한 세션이 어떤 이벤트로 시작되는지
- **계속 참여한 사용자 vs 이탈한 사용자의 첫 주 행동 비교**: 두 그룹이 첫 주에 무엇을 다르게 했는지

> 이 데이터는 실험이 아닌 관찰 데이터이므로, 위 분석에서는 **상관관계까지만** 말할 수 있다. 예를 들어 "첫 주에 X를 한 사용자의 리텐션이 높다"고 할 수는 있다. 하지만 "X가 리텐션을 높인다"는 인과는 주장하지 않는다.
